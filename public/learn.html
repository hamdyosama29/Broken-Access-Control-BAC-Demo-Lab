Understanding Broken Access Control (BAC)

What Happened?

In the Vulnerable version, when you visited the dashboard, the page briefly showed a "Loading..." table before declaring "Access Denied". While the UI looked secure because no sensitive data was ever rendered on the screen, opening a proxy like Burp Suite reveals the truth: the frontend made a request to GET /api/get-users/, and the server actually responded with the full list of sensitive admin users.

Why is it Vulnerable?

The vulnerability exists because the application relied solely on Frontend Authorization to protect the data. The frontend logic correctly determined that the user (Role: USER) was not authorized to view the page, so it hid the table and ignored the API response. However, the backend API completely failed to verify the user's role before returning the data.

Why hiding the UI is not security?

Frontend code (HTML/JavaScript) executes in the user's browser, meaning it is fully under the user's control. An attacker doesn't need the frontend to display the data; they can simply intercept the API request in Burp Suite, or use a tool like curl to fetch the data directly. Hiding elements via CSS or JS is a UX (User Experience) feature, not a security boundary.

Difference between Authorization Types

  • Frontend Authorization: Good for UX. It helps hide buttons and navigation links that the user shouldn't click. (e.g., hiding the "Admin Settings" button).
  • Server-side (API) Authorization: Mandatory for Security. The server must verify the identity and permissions of the user making the request before performing the action or returning any data.

What should the server do? (Remediation)

  • Always verify authorization on the backend. Do not trust the client.
  • Implement Role-Based Access Control (RBAC) or Attribute-Based Access Control (ABAC) at the API level.
  • Least Privilege: Only return the exact fields and records the user needs and is authorized to see.
  • Return proper HTTP status codes (like 401 Unauthorized or 403 Forbidden) when access is denied.
